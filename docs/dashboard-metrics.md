# Dashboard metrics

Both roles load the cohort and permitted profiles/tasks/requirements/submissions/events/projects/milestones/blockers through the ordinary browser Supabase client. RLS remains authoritative. No database records are inserted or rewritten for dashboard display.

Intern task completion is completed personally assigned tasks / all personally assigned tasks. Shared view-only tasks appear in the list but do not affect this percentage. Lead task completion is completed cohort tasks / all cohort tasks, including shared tasks. Empty denominators display an em dash.

Requirement status uses an individual submission if present; otherwise the existing requirement status is a legacy fallback. Completed/in-review states are retained; outstanding requirements become overdue at their exact `due_at` cutoff, or at the following midnight in Asia/Manila for a date-only deadline. The cutoff matches submission editing locks. A shared requirement applies to each current intern; an assigned requirement applies only to its assignee. Leads see the sum of these individual requirement obligations.

Team groups come from team memberships and team names, with profile team_name as a legacy fallback. Team progress uses members' assigned tasks, excluding shared cohort tasks. Unassigned interns remain visible in the intern table. Review queue counts in-review submissions for visible applicable requirements. Drill-down shows selected team members or an intern's tasks, requirements, and blockers. Project task and milestone progress is on the Projects page.

Upcoming events exclude records whose start time has passed. Suggested next action uses personally assigned unfinished/non-review tasks, then pending requirements with open deadlines. Earliest overdue task wins; otherwise nearest deadline wins, with tasks before requirements on ties. If no dated item remains, an open blocker linked to an incomplete milestone wins, ordered by milestone due date then blocker ID. Resolved blockers and completed milestones are excluded. Expired requirements remain in overdue lists but are locked for intern submission, so they are not actionable suggestions. The card says “Suggestion” and shows the reason and due date when present. The dashboard and assistant snapshot use the same shared deadline and recommendation functions. Assistant priorities are bounded to the permitted records in its snapshot; truncation is disclosed. Agenda ordering compares timestamp instants, including mixed timezone offsets. Cohort week and duration come from starts_on/ends_on, independent of work completion.

Dashboard metrics, shared submissions, empty states, permission-related rendering, role refresh and management interactions pass automated tests. Production build and local browser lead/intern walkthrough pass. A deployed lead/intern session test remains outstanding.
